## Engineering Approach

I prefer to treat architecture as a sequence of explicit decisions rather than a diagram created after implementation:

**Problem → Requirements → Constraints → Alternatives → Trade-offs → Decision → Implementation → Validation**

I value simple solutions, clear responsibility boundaries, documented decisions and systems that are understandable not only when they are designed, but also when they need to be changed years later.
